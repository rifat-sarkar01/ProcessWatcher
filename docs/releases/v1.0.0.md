# Process Watcher v1.0.0

**Prepared:** 2026-11-04 · **Status:** draft, not yet published

Process Watcher checks a recorded physical procedure against its written SOP and flags
missed, out-of-order and wrong-tool steps with timestamps, plain-language explanations
and evidence cut from the real video. The compliance decision comes from a deterministic
aligner over model-supplied perception, never from model prose.

This release packages the hackathon build for a reliable local showcase on Windows.

## Highlights

- **Windows one-click demo.** `Start-ProcessWatcher.bat` checks prerequisites and ports,
  starts the API in `PW_MODE=demo`, starts the Vite frontend, waits for both health
  checks, verifies the frozen pack, and opens the demo gallery in the browser.
  `Stop-ProcessWatcher.bat` stops only the processes the launcher started.
- **Offline demo gallery.** Three committed, checksummed keyboard-cleaning cases open
  with video playback, the dual-lane timeline, findings, real-frame evidence and
  watermarked illustrations. Demo mode makes no outbound Meta API calls and does not
  read `.env`.
- **Auditable evidence.** Every finding carries step ids, track ids, timestamps and a
  real frame; AI illustrations are labelled and never counted as evidence.
- **Repeatable results.** The dev and held-out evaluation tables, ablation notes and
  failure analysis are in `docs/results/`.

## Demo cases

| Case id | What it shows |
|---|---|
| `keyboard-compliant` | The SOP is followed; only a review-level note remains. |
| `keyboard-missed-tilt` | Step 1 is omitted and flagged with confidence 1.0. |
| `keyboard-heldout-missed-blower` | A held-out clip with the blow-air step missing. |

## Quickstart (Windows)

Requirements: Windows 10/11, [uv](https://docs.astral.sh/uv/) with Python 3.12, Node.js
22.12+ with npm, and ffmpeg only for analysing new clips. The demo cases need no API key
and no network.

First-time setup from the repository root:

```bash
uv sync
npm --prefix web ci
```

Then double-click `Start-ProcessWatcher.bat`, or run it from a terminal. The gallery opens
at `http://127.0.0.1:5173/demo`; launcher logs are under `.runtime\logs\`. Double-click
`Stop-ProcessWatcher.bat` to stop it.

Manual start on any platform:

```bash
PW_MODE=demo uv run uvicorn pw.api.main:app --port 8000
npm --prefix web run dev
```

## Live mode

Live mode is separate from the demo launcher. Copy `.env.example` to `.env`, set
`META_API_KEY` and `PW_ACCESS_CODE` locally, never commit the file, and run the API with
`PW_MODE=live`. Live runs spend money and send frames to the Meta API; the demo does
neither. Check configuration with `uv run pw config`, which prints `set`/`missing` and
never the secret values.

## Not included

- No standalone executable or installer. This is a local web application that requires
  Python 3.12 (via uv) and Node.js 22.12+ (via npm).
- No live model call is made by the launcher or the demo cases.
- The release notes are prepared in this file; publishing a GitHub Release remains a
  manual, explicitly approved step.

## Known limitations

- Short, similar actions (for example wipe keycaps vs wipe frame) are under-detected, so
  compliant clips can carry high-confidence `missed` findings.
- Wrong-tool substitutions are often reported as missing steps, and out-of-order findings
  can sit in the review lane below the flag threshold.
- Recognition needs a clear view; long occlusion can yield `procedure_not_recognized`.
- The verifier improves explanations more than verdicts.

See `README.md` and `docs/results/failures.md` for the full measured results and failure
analysis.

## Security and privacy

Runs stay on the local filesystem under `runs/`; there is no database and no third-party
analytics. Model calls only happen through `pw.clients`, which records them in a local
ledger. Demo and replay modes are cache-only. Secrets belong in the ignored `.env` file;
`.env.example` contains placeholders only.
